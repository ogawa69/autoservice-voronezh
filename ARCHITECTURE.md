# Архитектура

Проект использует упрощённую feature-sliced структуру с группировкой по функциональным модулям. Главная цель — держать связанный код рядом и не превращать `components` в общий склад.

## Слои

Зависимости направлены сверху вниз:

```text
app → pages → sections → features → shared
                    ↘ content
```

- `app` подключает глобальные стили и провайдеры, запускает страницу;
- `pages` собирает готовые секции в маршрут или экран;
- `sections` содержит самостоятельные крупные блоки страницы;
- `features` реализует пользовательские сценарии, которые могут использовать разные секции;
- `shared` содержит независимые элементы интерфейса и общие хуки без бизнес-контекста;
- `content` хранит типизированные данные, отдельно от представления.

Модуль не импортирует код из слоя выше. Между соседними модулями предпочтителен импорт через их публичный `index.ts`.

## Устройство модуля

Корень функционального модуля выглядит так:

```text
module-name/
├── ModuleName.tsx
├── styles.css
├── types.ts
├── index.ts
├── components/
│   └── ChildComponent/
│       ├── ChildComponent.tsx
│       ├── types.ts
│       └── index.ts
├── hooks/
├── model/
└── lib/
```

Обязательные части корня:

- `ModuleName.tsx` — главный компонент и точка сборки модуля;
- `styles.css` — стили этого модуля;
- `types.ts` — публичные контракты и типы свойств;
- `index.ts` — минимальный публичный API.

Подпапки добавляются по необходимости:

- `components` — только внутренние визуальные части модуля;
- `hooks` — состояние, эффекты и координация поведения;
- `model` — чистая предметная логика, константы и переходы состояний;
- `lib` — небольшие чистые вспомогательные функции.

## Правила компонентов

1. Один React-компонент — один `.tsx`-файл.
2. Внутренний компонент не объявляется в файле родительского компонента.
3. Главный компонент остаётся короткой композицией, а состояние и эффекты выносятся в хуки.
4. Переиспользуемый дочерний компонент получает собственную папку в `components`.
5. Типы свойств хранятся в соседнем `types.ts`, если у компонента есть отдельный контракт.
6. Стили принадлежат модулю и лежат рядом с его главным компонентом.
7. Внешний код импортирует модуль через `index.ts`, не обращаясь к его внутренним папкам.

Правило «один компонент — один файл» и ограничение размера компонентных файлов проверяет ESLint.

## Контент

Демонстрационные данные находятся в `src/content/demo`. Компоненты не должны дублировать адреса, телефоны, цены, акции или отзывы строками внутри JSX. Это позволяет заменить демоданные реальным источником без переработки интерфейса.

## Импорты

Для кода внутри `src` используется алиас `@`:

```ts
import { PricingSection } from "@/sections/pricing";
```

Относительные импорты используются внутри одного модуля. Глубокий импорт во внутренности другого модуля считается нарушением границы.

## Проверка изменений

Перед объединением изменений должны пройти:

```bash
npm run typecheck
npm run lint
npm test
npm run build
npm run check:bundle
```

Эту последовательность повторяет CI на Node.js 22. Проверка bundle budget не даёт стартовому JavaScript снова вырасти выше установленного лимита.
